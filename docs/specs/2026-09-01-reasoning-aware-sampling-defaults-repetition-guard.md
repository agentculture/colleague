# reasoning-aware sampling defaults + repetition guard (#479)

> Colleague sends each model's recommended sampling profile on every turn — a thinking profile when a reasoning rung is armed, a non-thinking profile when effort is off — instead of hard-coded greedy decoding; a model-independent guard cuts a turn whose reasoning has started repeating itself instead of riding it into the output budget; and a long turn keeps reporting liveness while it runs, so a runaway is visible while it happens rather than at the post-mortem.
> instruction: The whole change is provable offline from two request bodies plus one guard unit test; the live arm proves it was worth doing, not that it works.

## Audience

- The colleague operator running work items on a Qwen3.8 vLLM rig, and every seat colleague builds (cortex, worker, deepthink, senses, evaluator, scout, subagent children, the distill child) — each of which today inherits one hard-coded temperature 0.0 regardless of whether its thinking is on or off.
  - instruction: Check that the resolved profile is observable for a named seat via config show and the run artifact, not only inferable from a request dump.

## Before → After

- Before: Every acting-seat completion posts temperature 0.0 with no `top_p`, `top_k`, `min_p` or penalty key, so an armed reasoning rung runs the model greedily in thinking mode — the decoding mode Qwen explicitly warns against. Measured consequence (docs/live-testing.md row 66, run 2bd306a6916a at low): turn 14 emitted 271,486 characters of one insight repeated verbatim until `finish_reason`=length killed the turn before any answer; run 4b74a1bd5a9b tripped the identical-calls guard with five identical `write_file` calls.
  - instruction: Reproduce from the preserved brief before changing anything, so the arm has a baseline it owns.
- After: Each seat's completion carries its model's recommended sampling profile chosen by the already-resolved effort rung — Qwen3.8 thinking (1.0 / 0.95 / `top_k` 20) when a rung is armed, Qwen3.8 non-thinking (0.7 / 0.80 / `top_k` 20 / presence 1.5) when effort is off — declared in the tracked .colleague/models.json so every clone and worktree reads the same table, and a model-independent guard ends a turn whose reasoning has begun repeating instead of letting it ride to the output budget.
  - instruction: Verify with `COLLEAGUE_DUMP_REQUEST` on one armed and one off-rung turn; the two bodies must differ in exactly the profile keys.

## Why it matters

- The repetition is not a model capability limit — turns 1 through 11 of the same run reasoned sharply and the model snapped back to 70-300 character turns after the harness retried with a tighter window. A decoding default nobody chose is burning entire work items, and it does so silently enough that only the #476 reasoning sidecar made the diagnosis a three-command read.

- No retry-without-sampling-keys path ships. - A tracked file reaches a worktree at HEAD, so an UNCOMMITTED edit to models.json does not reach a running work item — the worktree is created at HEAD on colleague/<id>. Tuning sampling mid-arc therefore means committing the change, and the arc says so rather than letting an operator wonder why an edit had no effect.
  - instruction: State it beside the file's documentation; it is the same rule every tracked file follows, but it will surprise someone mid-measurement.

## Non-goals

- This arc does not make sampling a per-turn or per-task decision. The profile is resolved WHERE THE SEAT IS BUILT (the thinking-effort precedent, CLAUDE.md #416) and keyed only by model + already-resolved rung; nothing inspects the task to pick values. Picking sampling per turn would be the excluded router in a new costume.
- Penalty tuning is explicitly deferred: Qwen's thinking recommendation is `presence_penalty` 0.0 / `repetition_penalty` 1.0, and the operator's comment 3 says an elevated thinking-mode presence penalty is only tested if the official sampler still loops — so the sampler change is isolated first and penalties are a clean later variable, never confounded into this arm.

## Assumptions

- The mechanism is the SHIPPED associate precedent, copied rather than absorbed: colleague/`associate_config.py` defines a frozen profile dataclass, a FIXED table, a recognised config key set and a resolver that ignores unparseable values. The new sampling table follows that shape for the effort-driven seats while `associate_config.py` keeps running its own lane, so the arc ships a proven pattern twice rather than an unproven unification once.
- An IN-turn cut is only possible on the streaming path: engines/`vllm_transport.py` accumulates reasoning deltas frame by frame (`_emit_content_and_reasoning_deltas`, `_StreamAcc`.`reasoning_parts`) so a tail-n-gram detector has incremental input there, while the blocking path only sees the finished message. Headless streaming is on by default (`COLLEAGUE_STREAM`=0 opts out), so the streaming path is the normal one — but the guard must degrade to post-turn detection when it is not.
- Per-seat propagation is free: seat builders set a plain `reasoning_effort_seat` attribute on their own dataclasses.replace copy (`vllm_payload.py`:153-180) and `_build_chat_payload` reads it per call, so a profile derived from that rung automatically follows deepthink, senses, evaluator, scout and subagent children without any new threading.
- The wire is pinned by fixture tests, so the payload change is provable offline: tests/`test_thinking_effort_payload_fixture.py` and tests/`test_associate_sampling.py` already assert exact request bodies, and `COLLEAGUE_DUMP_REQUEST` (`vllm_openai.py`:314) dumps the outgoing payload for a live check.

## Decisions

- Sampling profiles are a built-in model-id keyed table in a new leaf module (Qwen3.8 first); an unmatched model id sends NO new sampling keys, keeping its payload byte-identical to today. Operator overrides layer on top from the tracked .colleague/models.json, resolved per value the way `associate_config.py` resolves its section — an unparseable value is ignored rather than refusing a run. There is no environment override rung for sampling values. Colleague never guesses a profile for a model it has not measured.
- The repetition guard runs in-turn on the streaming path — a tail-n-gram detector over the reasoning accumulator aborts the SSE read past a repeat threshold — and post-turn on the blocking path, where the same detector runs once on the finished reasoning text and records the same warning. One detector, two call sites, one warning shape.
- The stream-liveness work folds into this arc rather than a separate issue.
- PROBED 2026-09-01 against the live gateway at localhost:8001 (Qwen3.8-27B-NVFP4): the lobes gateway forwards the vLLM extension keys and vLLM honours them. A completion carrying temperature 1.0 / `top_p` 0.95 / `top_k` 20 / `min_p` 0.0 / `presence_penalty` 0.0 / `repetition_penalty` 1.0 plus `chat_template_kwargs` returned HTTP 200, and the discriminating probe settles that they are not merely tolerated: `top_k` 1 at temperature 2.0 returned three BYTE-IDENTICAL completions, while the same request without `top_k` returned three entirely different ones. The fourth carve-out therefore rests on a measurement, not an expectation.
- PROBED 2026-09-01: `presence_penalty` 1.5 does not suppress tool calling on the non-thinking profile. Six completions on one tool-using brief (two tools offered, `enable_thinking` false, temperature 0.7 / `top_p` 0.80 / `top_k` 20) emitted two well-formed parallel tool calls every time, at `presence_penalty` 1.5 and at the 0.0 control alike — no degradation, no malformed arguments. The Qwen card's instruct profile is therefore safe to apply to colleague's effort=off seats, which are exactly its tool-calling seats. Honest limit: six samples on ONE brief shape, not a guarantee across every tool surface.
- Precedence: an explicit flag beats the .colleague/models.json table, which beats the builtin model profile, which beats the existing default. `COLLEAGUE_SAMPLING`=0 short-circuits the whole chain to send nothing. The only value-carrying environment rung is the DEPRECATED `COLLEAGUE_TEMPERATURE`, which keeps its current meaning for one release and then goes; no new value-carrying environment knob is added, which is what stops a single scalar collapsing a model's two halves.
- The sampling knobs are SPLIT by half: a thinking value and a non-thinking value are separately settable for every field in the profile. A single value that silently applies to both halves is not acceptable — it collapses a two-halved model card into one number and makes an arm that looks like it measured the card actually measure something else.
- Sampling is configured by FILE, with one environment escape hatch. The table lives in the tracked .colleague/models.json — JSON, not YAML, because PyYAML is forbidden here (stated in identity.py, tui.py, `identity_mint.py` and explain/`catalog_ops.py`) and tests/`test_zero_deps.py` allow-lists exactly agentfront. `COLLEAGUE_SAMPLING`=0 is a PERMANENT per-process kill switch sending no sampling keys at all: it carries no value, so unlike a global temperature it cannot flatten a model's two halves, and it is what makes parallel A/B arms and a byte-identical control possible on a file every process on the checkout shares. `CONVERTIBLE_TEMPERATURE` is removed immediately; `COLLEAGUE_TEMPERATURE` is DEPRECATED for one release — still read, still applied, plus a loud warning naming the file that replaces it — and removed the release after.
- The associate fold-in is DEFERRED to a follow-up, not shipped here. colleague/`associate_config.py` stays untouched: its AssociateProfile carries `enable_thinking` and `max_tokens`, which are a template toggle and a budget rather than sampling keys; its half is selected by profile NAME (depth/triage) and never by the effort rung; and its branch in `_build_chat_payload` runs before the effort fragment entirely — so role=associate rows would need private semantics and a second half-selection authority inside the supposedly single system. The lane is also measured on different hardware with reruns still pending. The arc ends with TWO sampling surfaces, documented honestly as two, and the fold happens once the table has a live arm behind it.
- PROBED 2026-09-01, closing the parked unknown: aborting the SSE read DOES stop generation at the origin. A streaming completion was cut client-side mid-stream and GPU utilisation fell from 95 percent to 3 within about six seconds and stayed there. The repetition guard's cut therefore saves real GPU time on a shared rig, not merely colleague's wall-clock. Caveat: utilisation was already 95 from a prior killed request, so what is measured is that closing every client connection returns the origin to idle.
- PROBED 2026-09-01: `presence_penalty` 1.5 does not degrade bulk code emission on the non-thinking profile. Asked for a ~120-line Python module at temperature 0.7 / `top_p` 0.80 / `top_k` 20, the 1.5 arm produced 154 and 198 line files with ZERO non-ASCII characters — no language mixing, the specific degradation Qwen's card warns about — against a 158-line control at presence 0.0, with comparable def and class density. Honest limits: two samples against one control, one task shape, and structural metrics only; correctness of the generated code was not evaluated.
- The sampling table lives in its OWN tracked file under .colleague/, not in config.json. It is added to the auto-written .gitignore allow-list the way commands/ and skills/ already are, so it is committed, shared with the team, and present in every clone and every throwaway worktree. config.json stays ignored and keeps the machine-specific endpoint and any `api_key`, so nothing in this arc can carry a secret or a localhost URL into git.
- The file is .colleague/models.json — tracked, allow-listed in the auto-written .gitignore beside commands/ and skills/, keyed by model then role then thinking-versus-non-thinking half. The name is settled against agents.json for four recorded reasons: agents is already a live boolean key inside config.json arming the #411 execution mode (`config_seats.py`:203), so the word has a settled and different meaning in this config directory; sampling is default-on while #411 is opt-in and byte-identical when unarmed, so a default-on path must not read an opt-in mode's file; card values are facts about a MODEL and many roles share one model, so keying by agent would duplicate one published fact across every seat that uses it and let the copies drift; and AgentProfile.`resolved_model` is explicitly trace data filled from RoleInfo, so #411 discovers models rather than declaring them. If an agents definition file is ever built, it REFERENCES models.json rather than absorbing it.
